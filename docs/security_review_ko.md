**날짜:** 2026-10-20  
**방법:** 공격면 4개 영역을 나눠 코드를 읽고(읽기 전용 점검 4건), 핵심 지적은 코드로 다시 확인했다. TTS 명령 주입은 같은 따옴표 처리로 재현했다.  
**범위 결정 (사용자, 2026-10-20):** High·Medium 전부 + P6 배포와 관련된 Low 를 고치고, 나머지는 기록한다. TTS 배치 파일은 파일·stdin 만 허용, 동의 뒤 관찰 범위가 넓어지면 끄고 다시 동의.

### 계획과 다르게 드러난 것 — 빌드 의존성 (보안 점검 중 발견)
- 한국어 cl 은 `/showIncludes` 줄을 콘솔 코드 페이지로 내보낸다. 949 인 셸(예: Git Bash)에서 빌드하면 ninja 가 접두어를 알아보지 못해 **그 빌드에서 컴파일한 파일의 헤더 의존성이 0개**가 되고, 이후 헤더만 바꾸면 다시 컴파일되지 않았다 (구조체 배치 불일치 → P5 에서 3D 패키지 거부로 드러남).
- `tools/build.ps1` 이 콘솔 출력을 UTF-8(65001)로 고정한다 (`c201bd6`). CI 는 매번 새로 빌드하므로 영향 없음. 로컬은 `-Clean` 으로 다시 빌드한 뒤 전체 회귀를 다시 돌렸다 (§2).

## 4. 이상 없음으로 확인한 것

- OAuth: PKCE S256(48바이트), state·nonce 32바이트·시도마다 새로, state 를 가장 먼저 검증, ID 토큰 RS256 서명(JWKS)·iss/aud/azp/exp/iat/nonce/sub, 갱신 시 새 ID 토큰 재검증·같은 계정 확인, discovery 의 issuer·같은 origin 검사.
- TLS: 인증서 검증 끄는 플래그 없음, TLS 1.2/1.3 만, 리디렉션 따르지 않음 (Bearer 토큰 유출 방지). 운영 엔드포인트는 https 고정.
- 토큰 저장: DPAPI(CurrentUser), 임시 파일 → 원자적 교체, issuer 별 파일.
- 로그: 토큰·인가 코드·인가 URL·이메일·대화 원문·모델 출력 없음 (길이·코드·request_id 만).
- 콜백 리스너: 127.0.0.1 만, `SO_EXCLUSIVEADDRUSE`, 헤더 64KB·본문 4MB·5초 읽기 제한.
- 패키지: 경로 정규화(`ResolveInside`), Lua 는 base 일부·table·string·math 만(바이트코드 거부, 메모리 4MB), cgltf 외부 URI 거부·`cgltf_validate`, 아틀라스 크기 검사, 내장 텍스처 2048px.
- 모델 출력: 행동은 허용 목록∩캐릭터 클립, 감정은 enum, 발화는 제어 문자 제거·길이 제한, 말풍선·대화창은 평문 (마크업 없음), Windows 음성은 SSML 아님.
- 설치: zip 서명·중앙 디렉터리 사전 검사, 시스템 tar.exe(전체 경로·NUL·핸들 목록·시간 제한), 재분석 지점 거부, 직접 복사, 같은 볼륨 작업 폴더, id 규칙·예약 장치 이름 거부.
- 시작 프로그램: exe 경로만 따옴표로, 시험은 별도 키. `ShellExecuteW` 대상은 고정(설정 파일·폴더·상수 URL·검증된 인가 URL).

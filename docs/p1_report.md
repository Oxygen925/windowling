## 2. 구현 요약

- `dp_core`: `world`(1D 구간 빼기, 착지 표면, 발 지지 폭, 최대화 창 규칙, 모니터 판정), `physics`(Falling/Grounded/Attached/Dragged, 가림 유예, 창 크기 변경 클램프, 화면 밖 복귀), `event_bus`, `scheduler`, `config`, `log` — Windows API 없음(`/FI` 강제)
- `dp_platform_win`: `WindowObserver`(WinEvent 6개 범위, 콜백은 표시만 하고 펌프 1회당 한 번 반영, `LOCATIONCHANGE`는 해당 창 사각형만 갱신 + Z-order는 최대 100ms 간격으로 재확인), `FullscreenDetector`(전경 창 덮음 비율 + 예외 목록, `SHQueryUserNotificationState`는 기록만)
- `apps/desktop-pet`: 단일 UI 스레드 루프. 물리·애니메이션 중에만 고해상도 one-shot 타이머(D14), 완전 정지 시 물리 정지(P1-D6). 위치만 바뀌면 `SetWindowPos`만(Present 없음), 여러 창은 `DeferWindowPos`로 묶음. topmost 는 표시·재표시 때만 설정(P1-D2)
- 테스트 에셋: 8프레임(걷기 0~3, look 4, drag 5, sit 6, fall 7, CC0)
- 개발용 명령행: `--pets=N --spawn=X,Y --no-behavior --force-walk --metrics=csv --duration=초`

## 4. 성능 비회귀 (§4.4, `tools/measure/p1_regression.ps1`)

Release, debug layer off, 60초 × 3회(안정화 10초), 커서는 펫에서 멀리. 값은 3회 중앙값. 원자료 `logs/p1/20261013_223457_regression`, R5는 `logs/p1/` 최신 `_regression`.

| ID | 시나리오 | CPU% (GetProcessTimes 60초 / PDH / 사이클) | Working Set | Present/초 | 기상/초 | 창 이벤트/초 | P1 허용 (§4.4) | 판정 |
|---|---|---|---|---|---|---|---|---|
| R1 | 1마리 정지 | 0.006 / 0.008 / 0.005 | 41.2MB | **0** | 5.9 | 0 | ≤ 0.05% | 통과 |
| R2 | 1마리 계속 걷기 | 0.165 / 0.156 / 0.156 | 41.0MB | 8.0 | 78.7 | 0 | ≤ 0.3% | 통과 |
| R3 | 창 이벤트 폭주 (부착 창 약 60회/초 이동) | 0.252 / 0.250 / 0.250 | 40.9MB | 0 | 74.6 | 59 | ≤ 1% | 통과 |
| R4 | 창 50개 열린 상태 정지 | 0.003 / 0.004 / 0.005 | 41.2MB | 0 | 6.0 | 0 | ≤ 0.05% | 통과 |

- 세 CPU 지표가 서로 0.01%p 안에서 일치(D15 교차 검증).
- 정지 상태 기상 5.9회/초 = 커서 확인 5회(200ms) + 측정 샘플 1회. 측정을 끄면 커서 확인만 남는다.
- R2 걷기: 물리 60Hz는 유지하고 창 이동 반영을 30Hz로 묶은 결과(묶기 전 시범값 0.389%).
- R5: 시스템 전체 훅 때문에 커서가 움직이는 동안 초당 약 62회 깨지만 비용은 0.036%.
- P0 기준(1마리 정지 0.003%, 30fps 0.111%, WS 약 40MB) 대비: 정지는 같은 수준, 걷기는 창 이동이 추가된 만큼 증가, 메모리는 +1MB 안팎.

## 4.1 전체화면 직접 출력 복귀 (P1-07, P1-D5)

- 2차 측정 2026-10-13 23:15 (`logs/p1/20261013_231519_fsrecovery`, 사용자 관리자 실행). Mindustry 전체화면, 60fps 상한. 게임 → 일반 창(3초) → 게임 복귀(8초)를 조건별 3회.
- 1차 측정(22:57)은 다른 창 전환이 6회 모두 실패해 무효. Alt 키 입력 후 `SetForegroundWindow` 로 전환하도록 고쳐 2차에서 6회 모두 성공(이 PC에서 확인).
- 펫 로그: 다른 창으로 가면 `fullscreen show` → 그 창 위에 착지, 게임으로 돌아오면 `fullscreen hide`(`SW_HIDE`) — 의도한 상황 재현 확인.

| 조건 | 다른 창 3초 동안 | 복귀 후 첫 직접 출력 프레임 | 복귀 후 1초 합성 비율 | 복귀 후 프레임 간격 p95 / p99 |
|---|---|---|---|---|
| 펫 없음 | 합성 179~180프레임 | +1 / +21 / +2ms | 0% | 17.6~17.9 / 18.5ms |
| 펫 실행 | 합성 179~180프레임 | +24 / +14 / +30ms | 0% | 17.8~17.9 / 18.5ms |

- **두 조건 모두 복귀 첫 프레임부터 직접 출력(Hardware: Legacy Flip).** 펫 조건이 10~20ms 크게 나온 차이는 한 프레임(16.7ms) 이내이고 PresentMon·스크립트 시각 정렬 오차 범위라 의미 있는 차이로 보지 않는다.
- 다른 창에 가 있는 동안의 합성 출력은 펫과 무관하게 창 전환 자체로 생긴다(펫 없는 조건에서도 동일).
- 결론: 숨김(`SW_HIDE`) 방식에서 **펫이 직접 출력 복귀를 막지 않았다**(P1-D5 원인 분리 완료). 고정 임계값은 두지 않음.

## 5. 확인된 사실과 검증이 필요한 사항

### 5.1 이 PC에서 확인됨

| 항목 | 근거 |
|---|---|
| VS 동봉 vcpkg로 manifest 설치·버전 고정 | 구성 로그 |
| `/FI` 강제 포함으로 `dp_core`의 `<windows.h>` 사용 차단 | 음성 테스트 |
| ctest가 한글 테스트 이름을 넘기면 실패 → 케이스 이름은 ASCII | ctest |
| **다른 프로세스에서 `SetWindowPos(HWND_TOP, SWP_NOACTIVATE)`를 해도 전경 창 위로 올라가지 않는다** (Z 순위 변화 없음). `HWND_TOPMOST`는 올라간다 | 시나리오 W6 진단 |
| 테두리 없는 창의 `SW_MAXIMIZE`는 작업 표시줄까지 덮어 전체화면으로 판정된다(규칙대로) | 시나리오 W7 1차 |
| 시스템 전체 `LOCATIONCHANGE` 훅은 마우스 커서 이동 이벤트(`OBJID_CURSOR`)도 전달해 커서가 움직이는 동안 앱이 깨어난다 (12초에 raw 590건) | 실행 로그 |
| 걷기 중 60Hz마다 창을 옮기면 CPU가 계획 허용치를 넘음(0.389%) → 창 반영을 30Hz로 묶어 0.156% | 비회귀 시범 |
| `DWMWA_EXTENDED_FRAME_BOUNDS`로 테두리 없는 대상 창 위치 오차 0px | W2 |

### 5.2 아직 검증하지 않음 / 다른 환경 미검증

| 항목 | 비고 |
|---|---|
| `EVENT_OBJECT_REORDER`가 어떤 Z-order 변경에서 오는지 | 미확인. 대신 위치 변경 시 Z-order를 100ms 간격으로 다시 읽는 방어 코드를 넣음(필요성 자체는 미검증) |
| 가상 데스크탑 전환·일시 중단 UWP 창이 cloak 로 걸러지는지 | 미확인 (W8 수동) |

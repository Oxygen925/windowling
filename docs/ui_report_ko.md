## 2. 구현 요약

### 2.1 창 공통 (`ui/ui_common`, `ui/app_window`)
- 다크 모드는 문서화된 API 만: 제목 표시줄 `DWMWA_USE_IMMERSIVE_DARK_MODE`, 배경·글자 `WM_CTLCOLOR*`, 컨트롤 `SetWindowTheme`. 여러 줄 입력은 `DarkMode_Explorer`(스크롤바도 어둡게).
- Windows 앱 모드를 바꾸면(`WM_SETTINGCHANGE "ImmersiveColorSet"`) 대화창·앱 창이 다시 칠한다.
- `AppWindow`: 창 클래스 등록, 커서가 있는 모니터 가운데·그 DPI 크기, DPI 변경 시 글꼴, Tab·Enter·Esc(`IsDialogMessage`). **모달 루프 없음** — 앱 메시지 루프가 `RouteDialogMessage` 를 부른다.
- 목록(설정 영역·캐릭터)은 소유자 그리기 ListBox (줄 높이·선택 색). ListView 를 쓰지 않아 UI-04 의 "ListView 머리글 다크" 항목은 필요 없어졌다.

### 2.2 동의 창 (UI-06)
- 내용 스크롤, "위 내용을 읽고 이해했습니다" 체크 뒤에만 "동의하고 켜기". X·Esc·취소·답 없이 닫힘 = 동의 안 함. 비활성 버튼에 명령을 직접 보내도 체크 없이는 동의하지 않는다 (시나리오 O1).
- 동의 버전 1 유지 (문구만 바뀜, 범위 같음).

### 2.3 설정 창 (UI-07)
- 일반·표시(언어·테마·펫 크기·화면 갱신·근접 반응·Windows 시작 시 실행) / AI 대화(시작 시 켜기·단축키·말풍선·이력·시간 제한) / 화면 관찰(간격·상한·자리 비움·앱 이름·허용 행동·제외 앱, **켜고 끄기는 없음 — 동의 필요**) / 음성·전체화면 예외(시작 시 켜기·대화 응답 읽기·엔진별 칸·속도·음량, 전체화면 예외 두 목록).
- 검사: 숫자로 못 바꾸면 그 칸, 다음은 설정 파일과 같은 범위 검사(직렬화 → 다시 읽기 → 경고의 `section.key` 를 그 칸으로).
- 저장: 디스크의 설정 파일을 다시 읽어 **창이 다루는 항목만** 덮어쓴다 (`CopyUiFields`, 한 목록). 이전 파일은 `config.toml.bak`, 임시 파일을 쓴 뒤 교체. 직접 쓴 주석은 사라진다 (창에 안내).
- 반영: 언어·테마·화면 갱신·근접 반응·단축키·관찰 간격·TTS 엔진은 즉시. **펫 크기만 다시 시작 필요** (창·영역·3D 카메라가 크기에 걸려 있어 실행 중 경로를 시험하지 않음).
- Windows 시작 시 실행: `HKCU\...\CurrentVersion\Run` 의 `DesktopPet` (사용자가 켤 때만). 시험(`--test-hooks`)은 `HKCU\Software\DesktopPet\TestRun` 만 쓴다.
- 트레이 "관찰 설정" 은 설정 파일 대신 설정 창의 화면 관찰 영역을 연다.

### 2.4 캐릭터 관리 창 (UI-08)
- 목록: 썸네일·이름·id·종류·띄울 수. **거부된 패키지도 목록에** (이유 표시, 사용자 폴더면 삭제 가능).
- 썸네일: 2D = idle 첫 프레임, 3D = 화면 밖 텍스처에 한 번 그린 idle 자세 (펫과 같은 렌더러·readback). 계획의 "한 번 그린 썸네일" 그대로.
- 시작할 때 띄울 수 → `[[pets]]` 저장 → 그 목록으로 다시 띄운다 (합계 최대 8, 0 이면 트레이만).
- 설치 (폴더·`.zip` 끌어다 놓기, "zip 에서 설치…"):
  1. zip: 첫 4바이트 서명 + **중앙 디렉터리를 직접 읽어** 검사 (`..`·절대 경로·드라이브·`:`·심볼릭 링크·암호화·zip64·크기·개수·깊이). tar 는 다른 형식(tar·7z 등, 하드 링크 가능)도 읽으므로 zip 만 넘긴다.
  2. 시스템 폴더 `tar.exe` (전체 경로, 표준 입출력 NUL, 상속 핸들 제한, 30초 제한)로 작업 폴더에 해제.
  3. 트리 검사: 재분석 지점(심볼릭 링크·정션) 거부, 개수·크기·깊이. 폴더 설치도 같은 검사, 복사는 `CopyFileW` 로 직접 (링크를 따라가지 않음).
  4. `LoadAsset` — 앱이 불러올 때와 **같은 검사** (manifest·경로·아틀라스/모델).
  5. 작업 폴더(`DesktopPet\install_tmp`, 사용자 캐릭터 폴더 밖·같은 볼륨)에서 `characters\<id>` 로 이동. id 는 manifest 규칙(영문 소문자·숫자·하이픈) + Windows 예약 이름(con·nul·com1 …) 거부.
  6. 같은 id 가 있으면 확인. 기존 사용자 패키지는 휴지통으로 (실패하면 멈춤). 기본 제공 캐릭터는 지우지 않고 사용자 패키지가 우선.
- 삭제: 사용자 폴더 패키지만, 확인 → 그 펫 제거·`[[pets]]` 에서 빼기 → 휴지통 → 다시 읽기. **시험은 휴지통 대신 바로 지운다** (사용자 휴지통에 시험 파일을 남기지 않기 위해).
- 시험 전용: `--test-hooks` + 명령 9001 = 설정 폴더 `test_install.txt` 의 경로 설치 (끌어다 놓기는 다른 프로세스에서 자동화할 수 없음).

### 2.5 환영 창 (UI-09)
- 첫 실행(설정 폴더 `ui_state.json` 에 기록)에만 **포커스를 빼앗지 않고** 표시. 트레이 "도움말" 은 앞으로 가져온다. 시나리오는 `DP_TEST_NO_WELCOME` 으로 건너뛴다.

## 4. 한계·계획과 다른 점

- **팝업 메뉴(트레이·펫 우클릭)는 다크 모드에서도 밝다** — 문서화되지 않은 API 없이는 바꿀 수 없다 (계획 §2.4 그대로).
- **패키지 검사 오류 문구는 한국어만** (`LoadPackage`·설치 검사 내부 문구). 영어 UI 에서도 이유는 한국어로 보인다.
- 관찰 상태 보기·AI 꺼짐 안내는 MessageBox 그대로 (정보 표시만).
- 설치·삭제 확인은 MessageBox (짧은 모달, 그 동안 펫이 멈춘다).
- zip 해제는 UI 스레드에서 한다 (상한 안에서 1~2초 이내 가정).
- 확인하지 않은 동작 `[검증]`: 실제 끌어다 놓기, 실제 휴지통 이동(시험은 바로 삭제), 실제 Run 키 등록 후 Windows 시작 시 실행, Windows 앱 모드 전환 중 다시 칠하기, 혼합 DPI 모니터 사이 이동.

## 5. 사용자 확인 항목

1. 트레이 메뉴 → 설정… : 언어·테마를 바꿔 적용하면 바로 바뀌는지, 문구·배치가 읽기 쉬운지.
2. Windows 설정에서 앱 모드(밝게/어둡게)를 바꾸면 열린 창이 따라 바뀌는지 (테마 "자동").
3. 캐릭터 관리… : 캐릭터 폴더나 .zip 을 창에 끌어다 놓아 설치되는지, 삭제하면 휴지통에 들어가는지.
4. 설정의 "Windows 를 시작할 때 실행" 을 켠 뒤 다시 로그인하면 실행되는지 (확인 뒤 꺼도 됨).
5. 화면 관찰 켜기(동의 창)·대화창이 어둡게/밝게 모두 읽기 쉬운지.

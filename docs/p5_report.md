## 2. 구현 요약

- **구조:** `CharacterAsset` 이 스프라이트 또는 `ModelAsset`(모델 데이터 + GPU 자원, 캐릭터마다 1개)을 가진다. 펫은 포즈와 MSAA 대상(`ModelView`)만 따로 가진다.
- **물리·행동:** 그대로. 3D 펫의 사각형은 높이 = `base_height × 배율 × DPI`, 너비 = 모델 비율이다. 발 = 아래 가장자리 가운데(물리의 `foot`).
- **카메라:** 기본 자세(스킨 적용)의 바운딩 박스로 크기·발 위치를 고정한다 (위·옆 15% 여유). 오른쪽·왼쪽 카메라의 창 비율을 같게 해 방향을 바꿔도 창 크기가 그대로다.
- **애니메이션:** `ActionFor()` 의 공통 행동 → manifest `[model.animations]` → glTF 애니메이션. 없으면 idle, 그것도 없으면 기본 자세. 애니메이션 중에는 `display.frame_rate`(30) 간격으로 그린다 (P5-R5 결정).
- **hit-test (P5-R2 결정):** 그릴 때 백버퍼를 staging 으로 복사(최대 10Hz)하고, 다음 프레임에 기다리지 않고 읽어 알파 마스크 → Region. 같은 마스크면 `SetWindowRgn` 을 생략한다.
  - **계획에 없던 처리:** Region 은 창의 보이는 부분도 자른다. Region 이 최대 0.1초 + 1프레임 늦게 따라오는 동안 움직이는 다리·꼬리가 잘리지 않도록 마스크를 **4px(DPI 비례) 넓힌다.** 넓힌 만큼은 투명해도 클릭을 받는다. 잘림이 실제로 안 보이는지는 확인하지 않았다 `[검증]`.
  - `input.hit_region = "clip"` 은 3D 에 적용하지 않는다 (항상 readback).
- **테스트 전용 인자:** `--render-dump=path.png` (펫이 그린 픽셀만, 화면 캡처 아님), `--test-hooks` (WM_COMMAND 9000 = GPU 재생성 강제).
- **pack-check:** 3D 패키지도 앱과 같은 로더·제한으로 검사하고, 매핑된 애니메이션 이름이 없으면 경고한다.

## 4.1 걷기 끊김 수정 (2026-10-19, 사용자 보고)

- **보고:** 여우가 걸을 때 약간 끊기는 느낌.
- **측정** (`--frame-log`, 진단 전용): Present·창 이동 간격은 33.3ms 로 고르다(p95 33.7ms). 모니터 180Hz = 30fps 의 6배라 화면 주기 문제도 아니다.
- **원인 1:** 창은 정수 픽셀로만 움직여 2.33px/프레임 걷기가 2·2·3px 로 번갈아 보였다 (프레임마다 속도 ±20%).
- **원인 2:** 같은 30Hz 틱 안에서 창 이동을 건너뛴 프레임은 새 위치 기준으로 그려 창과 내용이 어긋났다 (248프레임 중 9).
- **수정:** 이번에 실제로 놓일 창 위치 기준으로, 반올림 나머지만큼 모델을 창 안에서 밀어 그린다 (가로·세로 서브픽셀 보정). 어긋난 프레임 9 → 0. P5 시나리오 9/9 유지.
- 사용자 재확인 대기.

## 4.2 착지 때 검게 보임 (2026-10-19, 사용자 보고)

- **확인:** 펫이 그린 픽셀(착지 전후 40장)에는 검은 픽셀이 없었다. 단색 배경 위 화면 프레임 측정(`tools/frame-grab`, 시험 창으로 덮은 사각형만 읽음)에서도 검은 픽셀 0 — **재현하지 못했다.**
- **추정 원인:** Region 은 보이는 부분도 자른다. 착지하며 자세가 Run → Survey 로 바뀔 때 Region 이 최대 0.1초 옛 자세로 남아 다리 일부를 잘랐고, 어두운 바닥(작업 표시줄)이 비쳐 검게 보였을 수 있다. 측정: 착지 구간에서 여우가 보이는 픽셀 최저 2865 (렌더 약 3100~3300).
- **수정:** 애니메이션 전환·낙하·드래그·착지 직후에는 readback 을 기다려 같은 프레임에서 Region 을 맞춘다. 수정 후 최저 3073. 평소(걷기·정지)는 10Hz 그대로. P5 시나리오 9/9, 비용 차이는 측정 오차 범위.
- 사용자 재확인 대기.

## 4.3 낙하 중 잘림 (2026-10-19, 사용자 보고)

- **보고:** 공중에서 떨어질 때 가끔 프레임이 잘린다.
- **원인:** 낙하 중 창 이동은 30Hz 틱, 그리기는 33ms 간격으로 따로 돌아 위상이 어긋났다. 창이 아직 옮겨지지 않은 프레임은 그 사이 내려간 거리(10~15px)만큼 모델을 창 안에서 밀어 그려 아래가 잘렸다.
- **수정:** 3D 펫은 그린 반복에서만 창을 옮긴다 → 창 위치와 내용이 항상 함께 바뀌고 보정은 1px 미만. 측정: 낙하 중 창 이동 28회 모두 그리기와 같은 반복(어긋남 0). P5 9/9, P1 12/12.
- 사용자 재확인 대기.

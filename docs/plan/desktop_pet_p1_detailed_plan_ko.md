## 0. 목적·범위

### 0.1 범위

- 정식 앱 `apps/desktop-pet` (P0 spike와 별도)
- Core 골격: EventBus, Scheduler(고정 스텝), Config, Logging, 의존성 규칙 강제
- WindowObserver: 시스템 전체 창 감시, 필터, 이벤트 병합, 주기적 재동기화
- WorldManager: 모니터·작업 영역, 창 표면(상단 노출 구간), Z-order 반영
- PhysicsSystem: 중력·착지·좌우 충돌·부착·낙하·화면 밖 복귀
- 입력: hit-test B, 클릭·드래그·우클릭 메뉴, 커서 근접 반응
- Sprite 렌더러: 테스트 에셋(CC0) 기반 공통 행동 `idle/walk/sit/fall/drag`
- 전체화면 자동 숨김, 세션 상태(잠금·절전·해상도 변경) 대응
- 트레이 메뉴 확장
- 테스트: 단위 테스트 + 자동 창 시나리오 테스트 + 성능 비회귀 확인

### 0.2 비범위 (P2 이후)

- 캐릭터 패키지 로더(`manifest.toml` 등), FSM/Lua, 다중 캐릭터 관리(P2)
- 말풍선 렌더링·대화창·AI·TTS(P3~P4). 단 말풍선 **창 배치 방식 결정**은 P1 초기에 한다(§6 #3)
- 캐릭터 간 충돌(기준선 §14: P2 이후 옵션)
- 다중 모니터 실환경 검증(D10 연기분은 P1-11로 두되, 환경 확보 전까지 단위 테스트로 대체)

## 3. 기술 설계

### 3.1 WindowObserver

**구독 이벤트** (`WINEVENT_OUTOFCONTEXT | WINEVENT_SKIPOWNPROCESS`, 전체 프로세스):

| 범위 | 용도 |
|---|---|
| `EVENT_OBJECT_CREATE` ~ `EVENT_OBJECT_HIDE` (CREATE, DESTROY, SHOW, HIDE) | 창 생성·소멸·표시 |
| `EVENT_OBJECT_LOCATIONCHANGE` | 이동·크기 변경 (가장 빈번) |
| `EVENT_SYSTEM_FOREGROUND` | Z-order 갱신 계기, 전체화면 판정 계기 |
| `EVENT_SYSTEM_MINIMIZESTART/END` | 최소화·복원 |
| `EVENT_SYSTEM_MOVESIZESTART/END` | 드래그 중 표시(고빈도 구간 진입·종료) |
| `EVENT_OBJECT_CLOAKED/UNCLOAKED` | 가상 데스크탑 전환, UWP |
| `EVENT_OBJECT_REORDER` `[검증]` | Z-order 변경 감지 보조 (발생 범위 확인 필요) |

**콜백 단계 필터 (가장 싸게 먼저):**
1. `idObject == OBJID_WINDOW && idChild == CHILDID_SELF`
2. `GetAncestor(hwnd, GA_ROOT) == hwnd` (최상위 창만)
3. 자기 프로세스 창 제외(훅 플래그 + 이중 확인)

**병합(coalescing):** 콜백에서는 `dirtySet.insert(hwnd)`만 하고 즉시 반환한다. 메시지 펌프 한 바퀴가 끝난 뒤 한 번만 `dirtySet`의 창 정보를 다시 읽는다. 드래그 중 이벤트가 수백 개 와도 갱신은 펌프 1회당 1번이다.

**창 정보 수집 및 유효 창 판정:**

| 조건 | 처리 |
|---|---|
| `!IsWindowVisible` | 제외 |
| `IsIconic` | 제외 (최소화) |
| `DWMWA_CLOAKED != 0` | 제외 (다른 가상 데스크탑·UWP 숨김) |
| `IVirtualDesktopManager::IsWindowOnCurrentVirtualDesktop == FALSE` `[검증]` | 제외 |
| 확장 스타일 `WS_EX_TOOLWINDOW`이면서 소유자 없음, 또는 `WS_EX_TRANSPARENT`·`WS_EX_LAYERED` 오버레이 | 제외 (다른 앱의 오버레이·툴팁) |
| 셸 창(`Progman`, `WorkerW`, `Shell_TrayWnd`, `Shell_SecondaryTrayWnd`) | 표면 아님. 작업 표시줄은 작업 영역으로만 반영 |
| `ApplicationFrameWindow` (UWP 호스트) | 자식 `Windows.UI.Core.CoreWindow` 유무·cloak로 판정 `[검증]` |
| 크기 < 최소 표면 폭(예: 펫 폭) 또는 높이 0 | 제외 |
| 사용자 제외 목록(실행 파일 이름) | 제외 |
| 관리자 권한 창 | 위치 정보는 읽힘 추정. 입력 통과는 UIPI 영향 `[검증]` (P0 E1 미확인) |

- 경계: `DWMWA_EXTENDED_FRAME_BOUNDS`(P0에서 `GetWindowRect`와 8px 차이 확인).
- **재동기화 (확정 P1-D6):** 초기 **30초** 간격으로 `EnumWindows` 전체 스냅샷과 비교해 누락·유령 창을 바로잡는다(§4.4 측정 결과에 따라 조정 가능). 세션 복귀·디스플레이 변경 직후에는 즉시 1회.

### 3.2 WorldManager·창 표면

- **월드 스냅샷:** 유효 창 목록(Z-order 순, `GetWindow(GW_HWNDNEXT)` 순회로 위→아래), 모니터별 작업 영역, 모니터 DPI.
- **상단 노출 구간 (1D 구간 빼기, 확정 P1-D1):** 창 W의 상단 선분 `[left, right] @ y=top`에서, Z-order상 W보다 위에 있는 유효 창 중 `top`을 세로로 포함하는(`T ≤ top < B`) 창의 `[L, R]`을 빼서 남은 구간 목록을 만든다.
  - **착지 가능 조건:** 남은 구간 중 **발 지지 폭 이상**인 구간만 착지 대상이다. 발이 구간 안에 다 들어가야 한다(초기 발 지지 폭 = 스프라이트 폭의 50%, 미확정 — §6.2).
  - **비사각형 창**(둥근 모서리, 창 Region을 쓰는 앱)은 `DWMWA_EXTENDED_FRAME_BOUNDS` 사각형으로 근사한다.
- **최대화 창 (확정 P1-D6):** 상단이 작업 영역 상단과 같아 그 위에 서면 펫이 화면 밖으로 나간다(P0 확인). **창 상단에서 작업 영역 위쪽까지 남은 높이가 펫 키보다 작으면 그 창 상단은 착지 불가**로 둔다.
- **작업 표시줄:** 작업 영역 하단이 바닥(기준선 §4.2). 작업 표시줄 자동 숨김이면 모니터 하단.

### 3.3 부착 중 가림 변화와 Z-order 정책 (A 채택, P1-D2)

펫 창이 topmost이면, 펫이 서 있는 창 X 위로 다른 창 Y가 올라와도 펫은 Y 위에 그려진다. 1D 구간 빼기는 **착지** 시점만 막는다. 부착 중에 가림이 생기는 경우의 정책이 필요하다.

| 안 | 동작 | 장점 | 단점 |
|---|---|---|---|
| **A. topmost 유지 + 가려지면 낙하** (**채택**) | 부착 지점이 노출 구간 밖이 되면 부착 해제 → 낙하(다음 노출 표면 또는 바닥) | 구현 단순, 항상 보임 | 창을 앞으로 가져올 때마다 펫이 떨어짐 |
| B. topmost 유지 + 가려지면 숨김 | 가려진 동안 펫 창 `SW_HIDE`, 다시 노출되면 표시 | 위치 유지 | 펫이 사라지는 느낌, 상태 관리 복잡 |
| C. 비 topmost, 호스트 창 바로 위 Z-order | `SetWindowPos(pet, hwndInsertAfter = 호스트 바로 위 창)`으로 호스트와 같이 가려짐 | 시각적으로 자연스러움 | 전경 변경마다 Z-order 재배치, 다른 앱 활성화 시 깜빡임·경쟁 `[검증]`, 바닥에 있는 펫은 별도 처리 |

- **P1은 A로 구현한다.** C는 별도 비교 실험으로 유지하며 P1 완료 조건이 아니다. 바닥(작업 표시줄 위)에 있는 펫도 topmost.
- **가림 유예 시간:** 부착 지점이 노출 구간 밖이 된 상태가 **유예 시간 동안 계속될 때만** 낙하한다(초기값 250ms, 미확정 — §6.2). 창 전환 애니메이션·순간 Z-order 변동으로 인한 불필요한 낙하를 막는다. 유예 중에는 위치·상태를 유지한다.
- **topmost 경쟁 회피(P1-D2):** 펫이 다른 topmost 창 위로 올라가려고 반복해서 `HWND_TOPMOST`를 재설정하지 않는다. 재설정은 펫 창을 처음 표시·재표시할 때와 숨김 해제 시에만 한다. 다른 topmost 창(전체화면 게임, 다른 오버레이)에 가려지는 것은 허용한다. 이 방식에서 펫이 일반 창 아래로 내려가는 경우가 생기는지 `[검증]`(Windows가 topmost 그룹 내부 순서만 바꾸는지 확인 필요).

### 3.4 PhysicsSystem

- **상태:** `Grounded(surface)`, `Attached(WindowId, localX, 접촉면)`, `Falling(vy)`, `Dragged`, `Climbing`(P1은 좌우 충돌만, 등반은 캐릭터 속성 도입 후 — P2).
- **고정 스텝 (확정 P1-D6):** **활동 중 60Hz**(렌더는 30fps). 누적 시간은 최대 100ms로 자르고 세션 복귀·숨김 해제 시 0으로 버린다.
- **정지 판정 (확정 P1-D6):** 모든 펫이 `Grounded/Attached`이고 속도 0, 애니메이션 정지 상태면 **이벤트가 올 때까지 물리 스텝을 멈추고 타이머도 해제**한다(D14). 창 이벤트·입력·행동 타이머가 깨운다.
- **창 부착:** `WindowId + localX + 접촉면`(기준선 §4.2). 호스트 창 이동 시 `footX = host.left + localX`, `footY = host.top`.
- **기준선 §4.2 대응표:**

| 상황 | 처리 |
|---|---|
| 창 상단 | 노출 구간 위면 착지 → `Attached` |
| 창 좌우 | 이동 중 펫 몸통이 창 측면과 겹치면 반대 방향 (등반은 P2) |
| 창 하단 | 비충돌 |
| 창 이동 | 부착 상대 좌표 유지. 드래그 중(MOVESIZE)에도 매 펌프마다 추종 |
| 창 종료·최소화·cloak | 부착 해제 → 낙하 |
| 창 크기 변경 | `localX`가 새 폭 밖이면 가장자리로 클램프, 노출 구간 밖이면 낙하 |
| 가려진 표면 | 착지 불가 (§3.2), 부착 중 가려짐은 §3.3 |
| 화면 하단 | 작업 영역 하단 착지 |
| 화면 밖·모니터 분리 | 가장 가까운 모니터 작업 영역 안으로 이동 후 낙하 |

### 3.5 입력

- hit-test **B**(ADR-09 잠정): 애니메이션 프레임·크기가 바뀐 펫만 Region 재계산(P0 방식).
- 클릭/드래그/우클릭/근접은 P0 구현을 이관. 드래그 시작 시 부착 해제, 놓으면 `Falling`.
- 커서 근접은 저주기 확인(P0 공통 기준선). 근접 반응 OFF 설정 시 확인 타이머 제거.
- 키보드 포커스 비탈취(`WS_EX_NOACTIVATE`, `MA_NOACTIVATE`) 유지.

### 3.6 렌더링·프레임 스케줄링

- 타이머: **hires 기본(D14)**. 애니메이션 또는 물리 활동 중에만 고해상도 one-shot. 정지·숨김·잠금 시 해제.
- **물리 이동의 창 반영 주기 (구현 중 결정):** 물리는 60Hz(P1-D6)로 계산하되, 걷기·낙하처럼 물리가 만드는 이동은 창 위치에 30Hz로만 반영한다. 부착 창을 따라가는 이동과 드래그는 즉시 반영. 걷기 CPU 0.389% → 0.165%(§4.4 R2).
- **Present 일괄화 (ADR-10 개선 방향):** 한 루프에서 콘텐츠가 바뀐 펫만 Present. 이동만 바뀐 경우 `SetWindowPos`만(Present 없음, P0 방식). 여러 창의 `SetWindowPos`는 `BeginDeferWindowPos`/`DeferWindowPos`로 묶는다(추천).
- `Present(1, 0)` 대기로 창 수만큼 지연이 쌓이는지 확인 — P0 소형 창 5마리 Present 지터 p95 5ms 원인 조사 `[검증]`. 필요 시 `Present(0, 0)` 또는 frame latency 설정 비교.
- 애니메이션 정의: 테스트 에셋 시트(6프레임)를 확장해 `idle/walk/sit/fall/drag` 행동별 프레임 목록을 코드 내 테이블로 둔다(패키지 형식은 P2).

### 3.7 전체화면 자동 숨김

- **판정(조합):**
  1. 전경 창이 해당 모니터 사각형을 거의 전부 덮는다(예: 98% 이상, 최대화 창과 구분하기 위해 작업 표시줄 영역까지 덮어야 함) — Mindustry는 `WS_POPUP` 2560×1440 창이었다.
  2. 보조: `SHQueryUserNotificationState`가 `QUNS_RUNNING_D3D_FULL_SCREEN`/`QUNS_BUSY`/`QUNS_PRESENTATION_MODE` `[검증]`
  3. 사용자 예외 목록(항상 표시/항상 숨김, 실행 파일 이름 기준)
- **숨김 동작:** 그 모니터의 펫 창을 **`SW_HIDE`**(P0 E6: 가려진 펫 창만으로도 게임이 DWM 합성으로 바뀐 사례). 렌더·물리·커서 확인·타이머 중지. 다른 모니터의 펫은 유지(기준선 기본값).
- **복귀:** 전경 변경 또는 창 위치 변경 시 재판정. 복귀 시 누적 시간 폐기, 위치 재검증.
- **측정 항목 (P1 완료 조건, P1-D5):** 숨긴 뒤 게임이 직접 출력(Legacy/Independent Flip)으로 돌아오는 데 걸리는 시간(PresentMon, 관리자), 그 구간의 게임 프레임 시간 영향, 판정 지연(게임 시작 → 숨김까지). **고정 임계값은 두지 않고 기록만 한다.**
- **원인 분리:** 직접 출력으로 돌아오지 않는 경우가 펫 때문인지 별도로 확인한다 — 펫 프로세스를 아예 띄우지 않은 상태에서 같은 전환(다른 창 전경화 → 게임 복귀)을 반복해 기준선을 만든다(P0 E6에서 펫 없는 G0도 합성 상태가 섞인 사례가 있음).
- 브라우저 F11·동영상 전체화면도 같은 규칙으로 숨긴다(기준선 §4.3: 완벽 분류 불가 → 예외 목록).

### 3.8 의존성 규칙 강제

- `dp_core` 타깃은 Windows SDK 라이브러리를 링크하지 않는다.
- `dp_core` 공용 헤더에 가드: `#if defined(_WINDOWS_) #error "dp_core must not include <windows.h>" #endif` (헤더 포함 순서에 따라 동작이 달라질 수 있어 CMake 별도 검사 타깃과 병행 — 추천).
- 리뷰 체크리스트: Core 타입에 `HWND`, COM 포인터, GPU 리소스 금지.

### 3.9 말풍선 창 배치 (별도 소형 창 확정, P1-D6)

B 방식은 Region 밖을 그리지 않는다(확인됨). **말풍선은 별도 소형 창으로 설계한다.** P1에서는 창 구조만 이 결정에 맞춘다(펫 창 크기는 스프라이트만 포함). 말풍선 구현은 P3.

| 안 | 내용 | 영향 |
|---|---|---|
| 펫 창 확장 | 말풍선 영역을 펫 창에 포함하고 Region에 추가 | 창 크기 변동, Region 갱신 증가 |
| **별도 말풍선 창** (**채택**) | 짧은 수명의 별도 소형 창(같은 Device) | 펫 창 구조 단순, 위치 동기화 필요 |

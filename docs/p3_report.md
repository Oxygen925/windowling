## 2. 구현 요약

- **SIWC 문서 조사** (계획 §1.1)
  - 2026-10-14 기준 `developers.openai.com/siwc` 의 오픈소스·로컬 앱 흐름을 따랐다.
  - 각 사실에 출처를 표시하고 "문서 기재·실연동 미검증" 으로 구분했다.
  - DevKit(비상업 라이선스) 코드는 쓰지 않았다. ChatGPT 로고 에셋은 받지 않았고 버튼은 텍스트만 쓴다.
- **`dp_ai`**
  - 인가 URL(최초 등록 / 다시 로그인), 콜백 검증(state 를 가장 먼저 확인)
  - 코드 교환·갱신·revoke 본문, 토큰 응답·범위
  - ID 토큰 클레임(alg·iss·aud·exp·nonce·sub), JWKS
  - 오류 분류표(errors-and-recovery), 증분 SSE 파서, Responses 요청(`store:false`·`stream:true`·`instructions`, 미지원 필드 없음)
  - 펫별 대화 이력(메모리, 최근 10턴), UTF-8 처리
- **`dp_ai_win`**
  - WinHTTP 동기 클라이언트. 다른 스레드에서 핸들을 닫아 취소한다.
  - 127.0.0.1 루프백 콜백(`SO_EXCLUSIVEADDRUSE`)
  - BCrypt RS256 검증, DPAPI 저장(원자적 교체)
  - `SiwcClient`(로그인·갱신·모델·스트림·로그아웃), `AiService`(작업 스레드 1개)
- **앱**
  - `[ai] enabled = false` 가 기본값이다. 끄면 P2 와 동작이 같다(회귀 테스트로 확인).
  - 켜면 펫 클릭 또는 단축키(기본 `Ctrl+Alt+P`)로 대화창을 연다.
  - 응답 중에는 펫이 `talk` 하고 말풍선에 응답 끝부분(160자)을 표시한다. 완료 8초 뒤 숨긴다.
  - 말풍선 처리:
    - 펫과 같은 30Hz `DeferWindowPos` 묶음으로 이동한다.
    - 텍스트가 바뀔 때만 다시 그린다.
    - 전체화면·사용자 숨김·GPU 재생성 때 함께 처리한다.
  - 트레이 메뉴: "이 펫과 대화", "AI 대화 사용" 토글. 토글은 실행 중에만 적용된다.
- **테스트용 명령행:** `--ai`, `--ai-endpoint=http://127.0.0.1:N` (127.0.0.1 만 허용), `--ai-open-url-file=path` (엔드포인트 재정의가 있을 때만)
- **캐릭터:** 테스트 캐릭터 2종에 `persona.md`(주황 반말·파랑 존댓말)와 `talk` 클립을 추가했다.
- **의존성:** vcpkg `nlohmann-json` 3.12.0#2 (P3-R1). 그 밖에는 OS 내장(WinHTTP·BCrypt·Crypt32·Winsock)만 쓴다.

### 구현 중 발견·수정

- **스트림이 실시간으로 보이지 않던 문제 (중요).**
  - 원인: 동기 `WinHttpReadData(8KB)` 가 버퍼를 채울 때까지 기다렸다. 그래서 짧은 응답의 delta 가 끝에 한꺼번에 도착했다.
  - 증상: 말풍선이 응답당 1~2회만 그려졌다.
  - 발견 경로:
    - 첫 시나리오(최종 상태만 확인)는 통과했다.
    - 성능 측정에서 스트리밍 중 Present 가 초당 약 4회(talk 애니메이션만)로 나왔다.
    - 그리기 횟수 진단(`bubble_draws`)으로 원인을 확인했다.
  - 수정: `WinHttpQueryDataAvailable` 로 도착한 만큼만 읽는다.
  - 재발 방지: 시나리오 C6(끝나기 전에 기록이 늘어남)·C7(말풍선 갱신 횟수)을 추가했다.
  - 앞선 스트리밍 성능값은 폐기하고 다시 측정했다.
- 취소 경합: 요청이 큐에서 시작되기 직전에 들어온 취소가 사라질 수 있었다.
  - `BeginRequest()` 에서 취소 상태를 먼저 초기화한 뒤 활성 요청을 확인하도록 순서를 바꿨다.
  - 갱신 직후 스트림 전송 전에도 취소를 다시 확인한다.
- 대화창 레이아웃: "Manage usage" 버튼과 모델 선택이 겹쳤다(PrintWindow 캡처로 발견). 남은 폭을 계산해 배치하도록 고쳤다.
- 시나리오 도구: 다른 프로세스 EDIT 컨트롤의 텍스트는 `GetWindowText` 로 읽히지 않는다. 문서화된 동작으로, `WM_GETTEXT` 로 바꿨다.

**측정 조건**
- Release 빌드, 60초 × 3회, 안정화 10초. 값은 3회 중앙값이다.

|---|---|---|---|---|---|---|---|
| I0 | AI 끔, 1마리 정지 (P2 M1 조건) | 0.006 / 0.007 / 0.004 | 41.9MB | 53.9MB | 7.4MB | **0** | 5.9 |
| I1 | AI 켬·로그인, 대화창 닫음, 1마리 정지 | 0.002 / 0.007 / 0.004 | 49.7MB | 54.5MB | 7.4MB | **0** | 5.9 |

**결과**
- **로그인한 채 쉬는 상태 (I1)**
  - CPU·기상·Present 는 AI 끔(I0)과 같다. 사이클 기준 둘 다 0.004% 이고, 기상은 둘 다 5.9회/초다.
  - 작업 스레드는 이벤트를 기다리고, 갱신 타이머가 없다. 그래서 정지 기준을 유지한다.
  - Working Set 은 +7.8MB 늘었다. 원인으로 추정하는 것: 대화창(Win32 컨트롤, 숨김 상태로 유지), WinHTTP·Winsock·BCrypt 모듈, 작업 스레드 스택. Private 증가는 +0.6MB 다.
- **스트리밍 중 (S1)**
  - CPU 는 0.23~0.27% 다. 기준선 §8.2 의 "1마리 일반 애니메이션 ≤ 1%" 안이다.
  - Present 12.3회/초는 말풍선 갱신과 talk 4fps 를 합친 값이다.
  - 회차별 GetProcessTimes 값은 0.161~0.334% 로 흔들렸다. 사이클 값은 0.226~0.234% 로 안정적이었다. P2-M1 과 같은 양상이라 두 값을 함께 적는다.
- **스트리밍 비용 줄이기 (적용하지 않음):** 말풍선을 delta 마다 그리지 않고 최대 10fps 로 묶으면 비용을 더 줄일 수 있다. 현재 값이 목표 안이라 지금은 적용하지 않았다.

## 5. 확인한 것 / 확인하지 않은 것

**확인함 (이 PC, 모의 서버):** §3 의 프로토콜·오류 복구·UI 흐름 전체, 비밀 정보 비노출, 종료 시간, P1·P2 회귀.

**확인하지 않음 `[검증]`:**
- **실제 OpenAI 서버와의 연동 전체.** 특히 다음 항목은 문서가 명시하지 않았거나 예시로만 나와 있다.
  - 토큰 교환 `grant_type` 필드
  - 최초 등록 포트 고정 여부
  - 실제 오류·모델 응답 형식
- TLS·프록시 환경에서 WinHTTP 핸들을 닫아 취소하는 동작
- 다른 앱이 전경일 때 대화창이 앞으로 오는지 (전경 잠금)
- 읽기 1회 수신 제한 60초: 실제 추론 모델이 첫 토큰 전에 60초 넘게 조용하면 `interrupted` 가 될 수 있다
- 알려진 경계 사례 (고치지 않고 기록만 함):
  - 로그인 콜백을 기다리는 중에 트레이에서 AI 를 끄면, 리스너가 시작되기 직전에 들어온 취소는 사라질 수 있다.
  - 이때 작업 스레드는 2초 뒤 분리되지만, 최대 5분 동안 1455 포트를 잡고 있을 수 있다.
  - 그 사이 AI 를 다시 켜면 `port_in_use` 안내가 나온다.
- 말풍선 가독성·체감, 페르소나 말투 차이 → 수동 체크리스트

  - 확인된 사실: 로그아웃 뒤에도 해제된 세션의 ID 토큰을 `id_token_hint` 로 보냈다. 문서는 "로그아웃 뒤에는 `id_token_hint` 생략" 이다 ([sign-in](https://developers.openai.com/siwc/token-sharing-open-source/sign-in)).
  - 힌트를 빼자 확인 페이지가 사라졌다(1차: 힌트 있음 → 확인 페이지, 2차: 힌트 없음 → 계정 선택만). 서버 내부 동작은 확인할 수 없으므로 원인은 이 관찰에 근거한 판단이다.
- **수정:** 로그아웃(revoke 성공·로컬 강제) 때 ID 토큰도 지운다. 다시 로그인은 저장된 client_id·host id 와 `login_hint` 만 보낸다.
  - 모의 시나리오 A1b·S2 기대값을 바꿨다 (47/47).
- **로그 민감정보 점검 (2차 로그):** JWT(`eyJ`)·이메일(`@`)·`access_token`·`refresh_token`·`code_verifier`·`code=`·`oaiapp_`·`Bearer` 모두 0건.
- 추가로 고친 것: 앱 로그 파일 이름이 `p0-spike_*.log` 로 고정돼 있었다. 이제 실행 파일 이름(`desktop-pet_*.log`)을 쓴다.

## 8. 사용자 결정·보완 (2026-10-14)

- **로그인 취소 경합·콜백 리스너 잔류 수정**
  - 로그인 요청 때(UI 스레드) 취소 표시를 초기화한다. 취소는 플래그와 이벤트로 함께 전달한다.
    - 그래서 작업 시작 전·`Listen` 직전에 들어온 취소도 사라지지 않는다.
  - 읽는 중인 콜백 연결도 `shutdown` 으로 즉시 깨운다.
  - 성공·취소·시간 초과 모두 포트를 즉시 놓는다.
  - 시나리오:
    - L1: 대기 중 취소 ×3, 1455 즉시 해제
    - L2: 시작 직후 취소 ×5
    - L3: 대기 중 AI 끄기 → 스레드 정상 종료·포트 해제
- **타임아웃 분리** (설정 가능, 스레드풀 타이머로 감시)
  - `[ai] first_token_timeout_sec` (기본 120): 시도마다 요청 전송부터 첫 글자까지. 503 백오프 대기는 세지 않는다.
  - `[ai] request_timeout_sec` (기본 300): 백오프·갱신을 포함한 요청 전체.
  - 결과는 `timed_out` (`first_token_timeout` / `request_timeout`) 이다.
  - 시나리오 TO1·TO2 로 확인했다. E4(503 백오프)는 영향을 받지 않는다.
- **대화 이력:** 캐릭터(펫)별 **20턴 RAM 보관**으로 바꿨다(`[ai] history_turns` 기본 20). 디스크 저장 기능은 없다(기본 비활성 유지).
- **최신 SIWC 문서·공식 DevKit 대조 (2026-10-14)**
  - DevKit 은 사실 확인용으로만 열람했고 코드는 복사하지 않았다.
  - `grant_type=authorization_code`·`refresh_token` 는 현재 구현과 같다. DevKit 이 이 값을 보내는 것을 확인했다.
  - 콜백 포트: 문서는 "포트만 달라도 된다"고 하고, DevKit 은 설정 포트 하나만 쓴다.
    - 결정: `[ai] callback_port`(기본 1455)를 등록·다시 로그인 모두에 쓴다. 다시 로그인 때 그 포트가 사용 중이면 빈 포트를 쓴다(문서 허용).
    - 최초 등록 때 포트가 사용 중이면 안내만 하고 다른 포트로 바꾸지 않는다.
  - discovery(`/.well-known/openid-configuration`)로 엔드포인트를 받는다. issuer·origin 이 일치할 때만 쓰고, 실패하면 내장값을 쓴다.
  - ID 토큰 검증을 보강했다: `iat` 필수, `azp` 가 있으면 확인, 허용 오차 300초→60초.
    - 갱신 응답에 새 ID 토큰이 있으면 서명·계정 일치를 확인한다(T3a·T3b).
  - plan usage 를 거부했던 등록은 다시 로그인할 때 `prompt=consent` 를 보낸다(A3c).
    - DevKit 동작이며 문서에는 없다 `[검증]`.
  - revoke 는 5xx·네트워크 오류일 때 1회 재시도한다(300ms 간격).
  - 오류 로그에 `x-request-id` 를 남긴다. 비밀이 아니고 진단용이다.
- **실연동 준비**
  - 트레이 "AI 연결 진단 (토큰 갱신·모델 목록)"을 추가했다. 토큰 갱신을 1시간 기다리지 않고 바로 검증한다(D1).
  - 로그에는 결과·HTTP 상태·오류 코드·request_id 만 남긴다.
- **P3 상태:** 실제 계정 연동을 확인하기 전까지 **최종 완료로 처리하지 않는다**.

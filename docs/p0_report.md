## 3. 측정 방법 관련 발견

- CPU 판정(D15): `GetProcessTimes` 60초 창 집계를 기준으로, 성능 카운터와 교차 검증한다. 다만 두 값은 같은 틱 기반이라 극저부하에서는 함께 0으로 나온다. 이 구간은 사이클 기반 보조 지표를 함께 적는다.
- wake-up 횟수는 커서 위치에 따라 달라진다(근접 시 33ms 주기). 측정 중에는 커서를 펫에서 멀리 둬야 S1 값이 재현된다. S0의 1회/초는 측정 샘플링 자체의 기상이다.

### 4.2 관찰 (설계 판단 자료)

- **E4 타이머:** hires와 msgwait의 CPU(0.111 vs 0.116%)·wake-up(34.4 vs 33.0/s) 차이는 작고, 실제 Present 지터 p95는 0.73ms vs 13.35ms. hires 기본값(D14)에 전력 측면 불이익은 이 측정에서 보이지 않는다.
- **E2 오버레이 전략 (5마리):** 소형 창은 CPU 0.333%·dwm GPU 0.19%·Present 150회/초(창마다 Present), 단일 오버레이는 CPU 0.129%·dwm GPU 0.076%지만 VRAM 37.1MB(QHD 전체 크기 swapchain). 소형 창 쪽의 Present 지터 p95가 5ms로 큰데, 한 루프에서 창 5개를 순서대로 `Present(1,0)`하는 영향으로 추정 `[미검증]`. 둘 다 녹색 범위라 결정은 CPU·VRAM 중 무엇을 우선할지의 문제다 — 계획서 §14 1행 추천(소형 창)의 재검토 근거.
- **E1 비용:** 정지 상태에서는 A/B/C 차이가 측정 하한 수준. 30fps에서 C(UpdateLayeredWindow)가 CPU 0.040%·메모리 15.5MB로 가장 가볍지만, 64px 스프라이트 2배 확대 기준이며 큰 해상도·3D에서는 CPU 복사 비용이 커진다. 입력 통과 품질은 수동 확인 전이라 E1 결론은 아직 없음.
- **측정 신뢰도:** 사이클 기반 값은 회차 간 편차가 작고(S3/single-5: 0.109–0.122), 틱 기반 판정값은 편차가 크다(0.018–0.197). 60초 단일 창이라 틱 양자화(15.6ms) 영향이 남아 있다 — 정식 측정(10분)에서 줄어들 것으로 예상.
- wake-up: 정지 상태 5.8/s = 커서 확인 200ms 주기(5/s) + 측정 샘플(1/s). 측정을 끄면 커서 확인만 남는다.

|---|---|---|---|---|---|---|
| G0 게임 단독 | 17.94 / 18.48ms | 18.09 / 22.21ms | 0.86 / 2.58ms | 5% | 0.19 / 0.04 | — |
| G1 소형 창 5마리 | 17.91 / 18.47ms | **22.23 / 22.25ms** | **6.07 / 10.79ms** | **81%** | **1.13 / 1.30** | 0.38 |
| G2 단일 창 5마리 | 17.94 / 18.49ms | **22.24 / 22.26ms** | **6.99 / 10.80ms** | **100%** | **1.01 / 1.17** | 0.17 |

- **게임 자체의 프레임 시간(Present 간격)은 모든 조건에서 같다.** 게임이 느려지지는 않는다.
- **펫이 보이는 조건(G1·G2)에서는 게임이 Legacy Flip(직접 출력)에서 DWM 합성(Composed: Copy with GPU GDI)으로 바뀌었다.** 그 결과:
  - 표시까지 지연이 평균 약 5~6ms 늘었다(0.86 → 6.07/6.99ms).
  - 화면 반영 간격 p95가 18.1 → 22.2ms. 22.2ms는 16.67ms + 180Hz 1주기(5.56ms)로, **일부 프레임이 한 주기 늦게 표시**된다는 뜻이다(60fps 게임에서 약한 끊김 가능).
  - DWM CPU 약 +0.9%p, DWM GPU 약 +1.2%p.
- 소형 창과 단일 창은 영향이 비슷하다(단일 창이 합성 100%로 조금 더 일관되게 합성).
- G3(숨김)는 G2 직후라 직접 출력으로 돌아가는 중간 상태(합성 61%)로 보인다 — 숨김 후 복귀에 시간이 걸리는 것으로 추정 `[미검증]`.
- **1차(21:23) 측정과 결과가 다르다**: 1차 G1은 Legacy Flip 100%였다. 1차에서는 펫이 전체화면 게임에 가려져 실제로 보이지 않았을 가능성이 있다 — 사용자 육안 확인 필요.
- D6 기준 판정: Present Mode 변화와 함께 **표시 지연·표시 간격 악화가 측정됨** → **노랑(조사 후 진행 가능) 잠정**. 체감 여부는 사용자 확인 필요. 기준선 §4.3의 "전체화면 게임 모니터에서 펫 자동 숨김" 정책(P1-07)이 필요하다는 근거가 된다.


#### 6.2.3 사용자 확인 반영 (2026-10-13)

- **1차·2차 모두 펫은 게임 위에 보이지 않았다.** 전체화면 Mindustry 창이 topmost 펫 창보다 위에 있었던 것으로 보인다(SDL/GLFW 계열 전체화면 창은 topmost로 뜨는 경우가 있음 `[미검증]` — 게임 창 확장 스타일은 게임 종료 후라 확인 못함).
- 따라서 2차의 합성 전환·표시 지연은 **보이지 않는(가려진) 펫 창이 존재·갱신되는 것만으로** 발생했다. 1차에서는 같은 조건에서 발생하지 않아 **재현성이 일정하지 않다**.
- **사용자 체감: 끊김 없음.** D6 기준 "측정 편차를 넘는 차이가 있으나 체감 영향 미미" → **노랑 유지**.
- 시사점(P1-07 설계 입력):
  - 전체화면 게임 위에 펫을 보여주는 것은 이 게임에서 불가능했으므로, 기준선 정책(게임 모니터에서 펫 숨김)과 충돌하지 않는다.
  - 숨김은 렌더 중지만이 아니라 **창 자체를 숨겨야(SW_HIDE)** 하며, 숨긴 뒤 게임이 직접 출력으로 돌아오는 시간을 확인해야 한다(G3 합성 61%).

### 6.4 잠정 판정·권장

| 항목 | 판정 |

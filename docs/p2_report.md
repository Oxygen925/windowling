## 2. 구현 요약

- **`dp_core`** (Windows 비의존, `/FI` 로 강제):
  - `character/package`: `manifest`·`animations`·`behavior` TOML 을 읽어 검증한다. 패키지 밖으로 나가는 경로는 거부하고, 크기 제한(P2-R7)을 적용한다.
  - `character/animation`: 클립 재생. 없는 행동은 idle 로 대체한다. 다음 프레임 시각을 계산해 타이머 마감으로 쓴다.
  - `behavior/fsm`: 쉴 때는 가중치로 행동을 고르고(idle·walk·sit), 이벤트(click·landed·drag·cursor_near)에 반응한다. 훅이 낸 결정은 검증한다.
- **`dp_script`** (Windows 비의존): `LuaBehavior` 는 펫마다 Lua 상태 1개다.
  - 허용 라이브러리는 base·table·string·math 뿐이다.
  - 호출 1회당 명령 100만 개, 상태당 메모리 4MB 로 제한한다.
  - 3회 연속 오류가 나면 스크립트를 끈다 ([ADR-07 세부](adr/ADR-07-lua-sandbox.md)).
- **앱:**
  - `CharacterAsset`(패키지·CPU 사본·GPU 텍스처)을 같은 캐릭터 펫끼리 `shared_ptr` 로 공유한다.
  - 펫마다 따로 가지는 것: 물리 몸체·FSM·Lua·애니메이션·창.
  - 물리 파라미터(걷기 속도·발 지지 비율)와 크기(`base_size`)는 패키지 값을 쓴다.
- **설정:** `[[pets]] character·count`, 합계 상한 8마리. 기본값은 `test-orange` 1마리로, P1 과 같은 동작이다.
- **트레이·우클릭 메뉴:**
  - 펫 추가 / 이 펫(또는 마지막 펫)의 캐릭터 바꾸기 / 펫 제거 / 패키지 다시 읽기 / 사용자 캐릭터 폴더 열기.
  - 런타임 변경은 저장하지 않는다.
- **개발·테스트 명령행:** `--pets=N --character=id --characters-dir=path --config=path --spawn=X,Y --spawn-step=DX --no-behavior --force-walk --metrics=csv --duration=초`
- **빌드:**
  - vcpkg 에 `lua` 5.5.0#1 을 추가했다 (기준선 `9e593bb…`).
  - `characters/` 를 실행 파일 옆으로 복사한다.
  - 3개 Preset 모두 경고 0 이다.

### 구현 중 발견·수정

- 패키지 우선순위를 폴더 이름으로 정하던 방식을 id 기준으로 바꿨다.
  - 폴더 이름 기준에서는 사용자 폴더 재정의가 로그 없이 덮어썼다.
  - 또 재정의 패키지가 깨져 있으면 동봉 캐릭터까지 사라졌다.
  - 시나리오 S1c 가 실패해 발견했다.
- `--no-behavior` 가 클릭 반응까지 같은 프레임에 idle 로 덮어쓰고 있었다. 이제 자율 결정만 막는다.
- 걷기 방향을 매 기상마다 FSM 값으로 되돌리던 문제를 고쳤다. 가장자리 반전은 물리가 한다.
- 걷기 창 이동 30Hz 제한을 펫마다 다른 위상에서 **공통 틱**으로 바꿨다. 여러 펫의 이동이 `DeferWindowPos` 한 번으로 묶인다.
- Lua 런타임 오류와 비활성화가 로그에 남지 않던 것을 고쳤다 (`[pet{}] lua error` / `lua disabled`).

**증가량 (기준선 §8.2 "1/3/5마리 증가량 측정"):**
- 정지: 마릿수와 관계없이 Present 0 이고, CPU 는 0.01% 미만이다. 정지 기준을 유지한다.
- 메모리: Working Set 은 1·3·5마리 모두 약 41.5MB 로 증가가 측정되지 않았다. 에셋 공유(참조 수로 확인) 때문으로 추정한다. 공유하지 않는 대조 측정은 하지 않았다. 측정한 펫은 모두 같은 캐릭터다. Private 은 약 +0.4MB/마리, VRAM 은 약 +0.1MB/마리다(펫 창마다 작은 스왑체인 1개).
- Present: 마릿수 × 8회/초다. 걷기 애니메이션 8fps 를 펫마다 그린다.
- 걷기 CPU 는 지표에 따라 다르게 나왔다:
  - **사이클 기준:** 0.18 → 0.31 → 0.41% 이다. 마리당 약 +0.06%p 로 선형보다 작게 늘어난다. 공통 30Hz 이동 틱 덕분에 기상 횟수가 거의 늘지 않았다(78 → 82회/초).
  - **판정 지표(D15, GetProcessTimes 60초):** 3·5마리 중앙값은 0.89·0.90% 이다. 회차 간 편차가 크다(W3 0.086~0.998%). PDH 는 같은 커널 시간 회계에서 나오는 값이라 GetProcessTimes 와 항상 일치한다. 그래서 이 편차를 교차 검증으로 걸러내지 못한다.
- 편차의 원인 분석:
  - **이 PC 에서 확인:** 걷기·정지 모든 회차에서 1초 샘플의 `proc_cpu_ms_delta` 가 정확히 15.625ms 의 배수다. 틱 단위 회계가 맞다.
  - 같은 양자 단위인데도 W3 3회차만 값이 작았다. 그래서 회차마다 시스템 타이머 해상도가 달라졌다는 설명은 맞지 않는다.
  - 방향은 마릿수에 따라 다르다. 1마리 걷기는 3회 모두 틱 값 < 사이클 값(과소)이고, P1 R2 는 세 지표가 일치했다. 3·5마리는 6회 중 5회가 틱 값 > 사이클 값(최대 약 3배 과대)이다.
  - 60초 동안 평균되지 않는 일관된 치우침이다. 기상 주기(60Hz 물리 + 30Hz 이동)와 64Hz 클럭 틱의 위상 관계 때문으로 추정한다. `[검증]` 이 메커니즘은 확인하지 않았다.
  - 사이클 값은 회차 간에 안정적이었다(W3 0.27~0.43%).
- 측정 중 문서 작업용 짧은 셸·python 명령이 몇 번 실행되었다. P1 측정 때는 다른 작업이 없었다. 영향은 다른 프로세스 쪽이라 무시할 수준으로 보지만 기록해 둔다.
- 목표 대조:
  - 기준선 §8.2 에는 다중 펫 CPU 목표가 없다(증가량 기록만 요구).
  - 1마리 애니메이션 목표 ≤ 1% 는 판정 지표로도 충족한다.
  - 5마리 걷기의 최댓값 1.099% 는 1회(W5 1회차)뿐이다.

## 5. 확인한 것 / 확인하지 않은 것

**확인함 (이 PC, 자동 검증):**
- 패키지 로드·검증·거부·우선순위
- 다중 펫·에셋 공유
- 설정·명령행·트레이로 캐릭터 교체
- Lua 훅 반영·샌드박스 제한·비활성화
- 펫 0마리 상주
- P1 동작 회귀 없음

**확인하지 않음:**
- 다른 크기(`base_size`)의 캐릭터를 섞은 경우
  - 표면 계산이 가장 큰 펫 높이 하나만 쓴다.
  - 테스트 캐릭터 2종은 크기가 같다.
- 큰 아틀라스(4096px 근처)의 메모리·로드 시간
- Lua 명령 100만 개의 실제 시간 상한
- 다중 모니터·배율이 다른 환경 (D10 연기)
- 트레이 메뉴 사용성, 캐릭터 차이 체감 → [수동 체크리스트](p2_manual_checklist.md)

- 상황: 다중 펫 걷기에서 판정 지표(GetProcessTimes)가 틱 단위 회계 때문에 회차 간 편차가 크다(§4, 15.625ms 양자 확인). 3·5마리는 사이클 값보다 일관되게 크게 나온다.
- 선택지:
  - (a) 이번 단축 측정값(중앙값 0.89·0.90%)을 그대로 기록한다.
  - (b) 10분 정식 측정으로 다시 잰다.
  - (c) 저부하 구간에서는 사이클 지표를 판정에 함께 쓰도록 D15 를 조정한다.
- 아직 결정하지 않았다.

## 8. 사용자 결정 반영 (2026-10-14)

- **P2-R1~R8:** 기존 구현을 **잠정 승인**한다.
- **크기가 다른 캐릭터 혼합:** 표면·착지 계산을 수정했다.
  - 문제: 표면을 "가장 큰 펫 키" 하나로 걸렀다. 그래서 작은 펫이 앉을 수 있는 창도 큰 펫 기준으로 막혔다.
  - 수정: 표면에 구간별 여유 높이(`headroom`)를 기록하고, 펫마다 자기 키로 착지·부착·걷기를 판정한다.
  - 회귀 테스트:
    - 단위 테스트 `Mixed pet sizes use their own headroom`
    - 시나리오 S7: 256px 캐릭터와 함께 실행해도 128px 펫은 위 공간 180px 창에 착지하고, 256px 펫은 바닥으로 간다.
- **테스트 캐릭터팩은 개발용으로만 쓴다.** 일반 배포판에는 기본 캐릭터팩을 넣지 않는다.
  - CMake 옵션 `DP_DEV_CHARACTERS` (기본 ON, 개발 빌드만 `characters/` 를 복사)를 추가했다.
  - 배포 패키지(P6)는 이 옵션을 OFF 로 빌드한다.
  - 이 결정으로 이전 D3("배포는 테스트 에셋만")을 대체한다.
- **다중 펫 CPU 편차(P2-M1):** 현재 측정값(§4)을 보존한다. 10분 정식 측정은 안정화 단계로 미룬다.

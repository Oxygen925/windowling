# ADR-13 캐릭터 패키지 형식 (schema_version 1) — 잠정

- 상태: **잠정** (2026-10-13). P2-R1·R6·R7·R8 은 사용자 확인 전 추천안
- 관련: 기준선 §6.2·§6.3, ADR-04(에셋과 인스턴스 분리), [P2 계획 §2.1](../plan/desktop_pet_p2_detailed_plan_ko.md), [P2 보고서](../p2_report.md)

## 결정

- 형식: **폴더 패키지만** 지원 (P2-R1). zip 은 배포 단계에서 다시 검토.
  ```
  <id>/manifest.toml
       render/sprite/atlas.png, animations.toml
       behaviors/behavior.toml (선택), custom.lua (선택)
  ```
- `manifest.toml` 필수 항목:
  - `schema_version = 1`
  - `id`: `[a-z0-9-]{3,40}`
  - `name`, `version`
  - `[license] name·author`: 배포 에셋의 출처를 기록 (D11)
  - `renderers` 에 `"sprite"`
  - `[sprite] atlas(.png)·animations`
  - `idle` 클립
  - 그 밖의 키(persona·ai·voice 등)는 읽지 않고 무시한다. 경고도 남기지 않는다. `behavior.toml` 의 알 수 없는 activity 만 경고한다.
- 경로: 모든 상대 경로는 패키지 폴더 안으로만 해석한다.
  - `..` 이나 절대 경로가 폴더 밖을 가리키면 거부한다 (`ResolveInside`).
- 크기 제한 (P2-R7):
  - 아틀라스 ≤ 4096×4096 이고 파일 ≤ 16MB
  - 프레임 16~512px
  - Lua 파일 ≤ 256KB
  - 디코딩한 아틀라스 크기와 애니메이션 프레임 범위가 맞는지 다시 확인한다.
- 실패: 그 패키지만 거부하고 로그를 남긴다 (`[library] rejected dir=.. errors=N` + 사유 목록). 앱은 계속 실행한다 (D12).
  - 펫이 0마리가 되어도 트레이에 상주한다 (D13).
- 검색 경로 (P2-R8), 뒤에 오는 경로가 우선:
  1. `<exe>\characters`
  2. 설정 파일 옆 `characters` (기본값 `%LOCALAPPDATA%\DesktopPet\characters`)
  3. `--characters-dir` (테스트용)
  - 같은 id 는 뒤 경로가 이긴다. 뒤 패키지가 깨져 있으면 앞의 같은 id 패키지가 남는다.
- 공유: 패키지 1개 = `CharacterAsset`(파싱 결과 + CPU 사본 + GPU 텍스처)을 `shared_ptr` 로 펫들이 공유한다.
  - 펫마다 따로 갖는 것은 위치·물리·FSM·Lua 상태·창이다 (ADR-04).
- 펫 구성: `config.toml` 의 `[[pets]] character·count`, 합계 상한 8마리 (P2-R6).
  - 트레이에서 런타임에 추가·교체·제거·다시 읽기를 할 수 있다. 이 변경은 저장하지 않는다.

## 근거 (확인한 것)

- 시나리오 S1~S6 은 23/23 통과 ([P2 보고서 §3](../p2_report.md)):
  - 5마리 2종을 동시에 실행했다.
  - 같은 캐릭터의 에셋 참조 수가 1 + 펫 수였다.
  - 사용자 폴더 재정의, 깨진 재정의일 때의 폴백을 확인했다.
  - 경로 이탈, 라이선스 누락, 큰 Lua 파일을 거부했다.
  - 펫 0마리일 때 트레이에 상주했다.
- 단위 테스트: 필수 항목 누락, 경로 이탈(`..`·절대 경로), id 형식, 스키마 버전, 크기 제한, 실제 동봉 캐릭터 2종 로드.

## 미확정·미검증

- zip 패키지, 패키지 서명, 파일 감시 자동 다시 읽기 (P2 범위 밖)
- 4096px 근처 큰 아틀라스의 메모리·로드 시간 (테스트 캐릭터는 512×64)
- 펫마다 다른 크기의 캐릭터를 섞었을 때 `petHeightForWorld_`(가장 큰 펫 높이)로 표면을 계산하는 방식의 영향

## 추가 (2026-10-19, P5: 3D 패키지)

```toml
renderers = ["gltf"]
[model]
path = "render/model/fox.glb"   # .glb 만 (외부 버퍼·이미지 파일 거부)
base_height = 80                # 100% 배율 화면 높이, 너비는 모델 비율
yaw_deg = 60                    # 3/4 시점 (-90~90), 왼쪽을 볼 때 반전
[model.animations]              # 공통 행동 → glTF 애니메이션 (없으면 idle, 그것도 없으면 기본 자세)
idle = "Survey"
walk = "Walk"
```

- 제한(추천, 미확정): glb 32MB, 삼각형 50k, 관절 128, 애니메이션 32, 이미지 8, 텍스처 2048².
- `[sprite]` 는 3D 패키지에서 선택. 둘 다 있으면 모델을 쓴다.
- 물리·행동은 스프라이트와 같다 (ADR-03). `behavior.toml`·`persona.md`·`[voice]` 도 같다.

## 추가 (2026-10-20: 점프·벽 타기, 선택 행동)

```toml
# behaviors/behavior.toml
jump_height = 2.5     # 더 높은 창 위로 뛸 때 최대 높이 (펫 키의 배수, 0.5~6)
climb_speed = 60.0    # 벽 오르기 px/s @96DPI (10~1000, 없으면 walk_speed × 0.6)
[activities]
jump  = { weight = 14, min = 1, max = 1 }
climb = { weight = 10, min = 1, max = 2 }   # climb 애니메이션이 없으면 경고 후 끔

# render/sprite/animations.toml (선택 행동: 없어도 경고 없음)
jump  = { frames = [16], fps = 1 }          # 올라가는 동안 (없으면 fall)
climb = { frames = [17, 18, 19], fps = 6 }  # 벽이 오른쪽인 그림 (왼쪽 벽은 앱이 뒤집는다)
```

- 공통 행동(`CommonActions`)은 그대로 7개다. `jump`·`climb` 은 선택 행동(`OptionalActions`)으로 받는다. 기존 패키지·테스트에 영향 없음.
- 점프: 60% 는 닿는 높이(`jump_height`) 안의 창 상단 노출 구간 중 가로로 가장 가까운 곳을 노린다. 없거나 나머지 40% 는 그 자리·걷는 방향으로 작게(키의 45%) 뛴다. 착지는 기존 낙하 판정 그대로이고, 올라가는 동안에는 착지하지 않는다.
- 벽 타기: 지금 면에서 걸어서 닿는 가장 가까운 벽을 고른다.
  - 창 옆면: 펫 키 이상 높고, 발 근처까지 내려오고, 옆면이 위 창에 90% 이상 보이고, 꼭대기에 올라설 자리가 있을 때. 꼭대기에서 창 위로 올라선다(`Landed reason=climbed`).
  - 화면 바깥 끝(다른 모니터와 맞닿은 끝 제외): 남은 높이의 60% 까지 오르고 벽 반대쪽으로 뛰어내린다.
  - 오르는 중: 창이 움직이면 따라가고, 닫히면 떨어지고, 옆면이 가려지면 가림 유예(P1-D2) 뒤 떨어진다.
- `behavior.climb = true` (P2 예약 자리)는 쓰지 않는다 — 경고 후 무시.
- Lua 훅도 `jump`(dir -1/0/+1)·`climb`(dir 0) 을 고를 수 있다. 물리가 할 수 없으면(뛸 자리·벽 없음) 1초 가만히.
- 시험 전용 인자(`DP_TEST_HOOKS`): `--force-activity=jump|climb`.
- 확인: 단위 테스트(점프·높은 창·창 옆면·가림·창 이동/닫힘·화면 끝·맞닿은 모니터·드래그), 개발 빌드에서 화면 끝 오르기·뛰어내리기·연속 점프 로그. 창 옆면 오르기·높은 창 점프는 실제 화면에서 아직 못 봄.

## 추가 (2026-10-20: 행동 사이 쉼, 창 사이 넘나들기, 펫끼리 인사·따라가기)

```toml
# behaviors/behavior.toml
rest_between = 1.0    # 행동과 행동 사이 가만히 서 있기 (초, 0~5, 실제 0.8~1.5배). 0 = 예전과 같음
greet = true          # 다른 펫(greet 를 켠)과 같은 면에서 마주치면 멈춰 마주 보고 인사 말풍선 (쌍마다 90초에 한 번)
[activities]
follow = { weight = 7, min = 1, max = 1 }   # 가장 가까운 펫을 최대 12초 따라가 잡기 (펫이 1마리면 쉼)

# animations.toml (선택 행동)
rest = { frames = [0, 0, 0, 1], fps = 5 }   # 없으면 idle
```

- 쉼: 결정이 끝날 때 다음 행동 전에 `rest` 를 넣는다. 착지 직후도 `rest` (rest_between > 0 일 때만). 0 이면 난수를 더 쓰지 않아 기존 결정 순서가 그대로다.
- 점프 목표: 더 높은 창뿐 아니라 같은 높이·낮은 창(내려가기는 `jump_height` × 1.5 까지), 가로는 키 × 5 까지. 바닥은 목표가 아니다 (가장자리에서 걸어 내려간다).
  - 후보마다 같은 고정 스텝으로 비행을 미리 돌려, **처음 내려앉는 면이 목표일 때만** 쓴다 (자기 창·중간 창에 걸리는 후보는 버림). 가까운 후보 3개 중 무작위.
- 벽 타기: 바닥 근처까지 내려오지 않는 떠 있는 창도, 아래끝이 `jump_height` 안이면 벽까지 걸어가 뛰어 붙은 뒤(위로 감속, `jump` 애니메이션) 오른다.
- 진단 로그: 점프·벽 타기를 계획할 때마다 후보 수와 빠진 이유 (`jump plan candidates= height= reach= room= blocked= ok=`, `climb plan windows= ...`).
- 인사·따라가기 판단은 `core/behavior/social` 의 순수 함수(같은 면 판정·인사 쌍·따라가기 한 단계). 끌림·낙하·벽 타기·말하기·말풍선·전체화면 숨김·일시정지 중인 펫은 빠진다. 새 타이머 없이 행동 갱신 때만 판단한다.
  - 따라가기: 같은 면이면 걸어가고, 다른 면이면 그 면으로 점프(`PlanJumpTo`, 1.5초마다 시도), 안 되면 그쪽으로 걷는다. 닿으면 "잡았다!"/"으악!" 말풍선, 잡힌 쪽이 `follow` 를 가졌으면 한 번 되잡으러 온다.
  - 말풍선 문구는 `lang/*.toml [pets]` 의 고정 문구 (AI·TTS 쓰지 않음).
- 기본 캐릭터(test-*, windowling)는 켜지 않았다 (시나리오·기본 동작 그대로).

## 추가 (2026-10-28: 하이파이브·부딪치면 튕기기·붙어 앉기·기차놀이)

```toml
# behaviors/behavior.toml
bump = true           # 같은 면에서 걷다 마주치면 둘 다 상대를 본 채 뒤로 폴짝 (쌍마다 15초에 한 번)
lean = true           # 둘 다 앉아 있으면 한쪽이 옆자리로 걸어가 둘이 붙어 앉음 (쌍마다 2분에 한 번)
[activities]
train = { weight = 4, min = 1, max = 1 }   # 이끄는 펫이 8초 걷고, 같은 면의 train 을 가진 펫 최대 3마리가 줄지어 따라옴

# animations.toml (선택 행동)
highfive = { frames = [20, 21], fps = 6 }  # greet 를 켠 두 펫이 둘 다 가지면 인사의 반쯤은 하이파이브 (상대가 오른쪽인 그림)
lean     = { frames = [22], fps = 1 }      # 없으면 sit
```

- 판단(마주침·붙어 앉을 쌍)은 `core/behavior/social` 의 `FindBump`·`FindLean`, 따라가기는 종류별 닿는 거리(잡기 0.9·기차 1.25·붙어 앉기 0.85 × 두 폭 평균)만 다르다.
- 기본 캐릭터는 켜지 않았다.

## 추가 (2026-10-28: 탑 쌓기 — 다른 펫 머리 위에 올라타기)

```toml
# behaviors/behavior.toml
head_height = 0.47    # 머리 꼭대기 높이 (키의 비율, 발에서 위로). 다른 펫이 올라탈 자리 (0.1~1, 기본 0.8)
[activities]
stack = { weight = 5, min = 1, max = 1 }  # 걷지 않는 가까운 펫(또는 그 탑의 맨 위) 머리로 뛰어올라 6~10초 앉아 있다가 뛰어내림. 3층까지

# animations.toml (선택 행동)
ride = { frames = [25], fps = 1 }  # 머리 위에 있는 동안 (없으면 sit)
```

- 물리: `BodyMode::Riding` (스텝 없음, 위치는 앱이 아래 펫 머리 `RiderFoot` 에 맞춤). `AimAtPoint` 로 머리 위 점을 지나는 점프를 계획하고, 고정 스텝마다 `CrossesHead`(내려오며 머리 높이를 지남 + 가로 허용 범위) 이면 올라탄다.
- 태운 펫은 `carry`(쉼 그림)로 가만히 있다. 태운 펫이 끌리거나·떨어지거나·사라지면 위 펫들이 아래부터 차례로 떨어진다. 창이 움직이면 창 위 펫과 그 위 펫이 함께 움직인다.

## 추가 (2026-10-28: 버그 잡기)

```toml
# behaviors/behavior.toml
bug_hunt = true    # 가끔 나타나는 버그를 쫓아가 잡음 (기본 false)

# animations.toml (선택 행동)
bug = { frames = [26, 27], fps = 10 }  # 버그 그림 (프레임 아래쪽에 작게). 이 그림이 있어야 사냥함
```

- 사냥할 펫(`bug_hunt` + `bug` 그림)이 있으면 시작 150초 뒤, 이후 3~6분마다 버그 하나가 사냥꾼 근처 위에서 떨어진다. 다른 놀이 중이 아닌 사냥꾼이 없으면 나오지 않고 10초 뒤 다시 본다.
- 버그는 그 캐릭터 그림을 쓰는 임시 펫(`isBug`, id 1000부터)으로, 걷기 속도 1.8배로 이리저리 움직인다. 쉬고 있던 사냥꾼들이 잡기 놀이(Tag)처럼 22초 동안 쫓고, 먼저 닿은 펫이 잡는다(`greet` + 말풍선). 25초 안에 못 잡으면 도망친다. 잡히거나 도망치면 바로 사라진다.
- 버그는 펫 수 제한·단축키·메뉴 대상·설정 저장·화면 관찰·다른 상호작용 대상에서 빠진다. 버그를 오른쪽 클릭하면 대상 없는 메뉴가 열린다.

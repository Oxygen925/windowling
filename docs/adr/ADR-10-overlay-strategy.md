# ADR-10 오버레이 창 전략 — 잠정

- 상태: **잠정 결정** (2026-10-13, 사용자 지시 + P0 단축 검증). 정식 측정 후 확정
- 관련: 계획서 §3.4, §14 1행, E2·E6 / 보고서 `docs/p0_report.md` §4, §6

## 결정

**캐릭터별 소형 창(공유 D3D11/DComp Device)을 우선 후보로 유지한다.** 화면 전체 단일 창은 E6 비교용으로 코드에 유지한다.

## 근거

| 지표 (5마리, 30fps) | 소형 창 | 단일 창 |
|---|---|---|
| 펫 CPU (단축 측정 60초×3) | 0.333% | 0.129% |
| 펫 CPU (E6, 게임 병행) | 0.438% | 0.116% |
| VRAM | 8.4MB | 37.1MB (QHD 전체 swapchain) |
| Present/초 | 150 (창마다) | 30 |
| DWM CPU (단축 측정) | 0.405% | 0.265% |

- 둘 다 계획서 CPU 목표(1마리 30fps ≤ 1%) 안이다. 단일 창은 CPU가 낮지만 VRAM이 화면 크기에 비례하고(4K·다중 모니터에서 증가), 화면 전체 topmost 창이라 입력·전체화면 앱 영향 범위가 넓다.
- E6에서 단일 창 조건(G2) 시작 직후 게임이 전경을 잃은 것이 1회 관찰됐다(원인 미확인).
- 소형 창의 CPU 증가는 창별 Present 횟수에 비례하는 것으로 보인다 → P1에서 프레임당 Present 일괄화, 정지 펫 Present 생략 등으로 줄일 여지가 있다.

## 미확정·미검증

- 전체화면 게임 영향(보고서 §6.2.2): 펫이 보이면 소형·단일 모두 게임이 DWM 합성으로 전환(표시 지연 +5~6ms, DWM CPU·GPU 약 +1%p). 오버레이 방식 간 차이는 작아 이 결정에는 영향 없음 — 대신 전체화면 자동 숨김(P1-07)이 필수
- 전체화면 게임 위에서 펫이 실제로 보이는지 육안 확인
- 다중 모니터·혼합 DPI 환경
- 정식(10분 × 3회) 측정
